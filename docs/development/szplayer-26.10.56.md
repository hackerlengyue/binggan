# SzPlayer 26.10.56 兼容性记录

本记录将提供的新版分析文档与更新前的代码对照。仓库没有旧版分析文档存档，因此不能据此断言每项算法差异都由播放器升级引入。分析文档按原文保存，仅将复现命令中的个人绝对路径替换为示例路径；其中 `analysis/` 下的参考脚本属于原分析环境，并未包含在本仓库中。

## 版本与校验值

| 项目 | 值 |
| --- | --- |
| 版本标识 | `MAC_sz_26.10.56` |
| universal 文件 SHA-256 | `801f49182b6b1f6c1d64d838feea1fcd207631a3561c27ef581599573facc743` |
| `softMd5` / `appMd5` | `d2901bdda0d5e3f86dddc450bf0fa7f9` |
| 计算方式 | `MD5(hex(SHA256(完整可执行文件)))` |

本次读取的本机播放器版本与 SHA-256 均与分析对象一致。内置此版本的校验值，同时保留 `MAC_sz_25.12.52`；不会把 arm64 slice 的校验值用于 universal 文件。显式配置和密钥文件内的校验值仍优先于内置记录。

## 实现差异与处理

| 分析文档结论 | 更新前的行为 | 本次处理 |
| --- | --- | --- |
| 主密码使用 AES-256-ECB/PKCS#7，密钥是 32 字节 ASCII | ECB 失败后尝试 CBC，未强制有效填充 | 新版只接受 ECB，严格校验填充；保留旧版 CBC 兼容 |
| 模式 `1` 固定使用 `pmn` 槽 | 与模式 `3` 一样按偏移换槽 | 固定选择 `passwords[pmn]` |
| 模式 `3` 按文件偏移选择槽位，范围为 1–180 | 整数半数向上舍入 | 按原算法计算浮点值，半数取偶 |
| `whenLong` 对应传入 C 的 `den1` | 引擎只读 `den` | 优先 `whenLong`，兼容 `den1`、`den` |
| `dts = (slot - 1) × pmn × den`，`num` 为 1 | 按响应出现顺序编号；可能把 `num` 当成 `pmn` | 新版反推实际槽位，保留空缺和不同槽的重复值，不从 `num` 推断 `pmn` |
| 每次主密码请求有独立 `uit` | 多个 `uit` 被判为混合用户；可能分开覆盖密码和 `uit` | 新版成对保存请求 `uit` 与响应密文，使用文件校验值和用户字段检查混合来源 |
| 服务端 `data.type = "1"` 表示密钥请求失败 | HTTP 200 仍可能提取密码字段 | 新版阻止使用错误响应和播放器占位密钥 |
| `<null>` 使用完整置换主密钥加 sample size | 只接受模式 `1`、`3` | 支持 `<null>`，无需槽位参数或分段密钥 |
| 模式 `4` 直接使用 `mimatuokeqian` | 不支持 | 支持显式导入 `getPwdData.mimatuokeqian`；不从网络主密码推测该值 |
| 字面量 `null`、缺失和空模式不能解密 | 可能从接口名称推断模式 | 新版拒绝缺失和空模式；响应中的 JSON `null` 规范为 `<null>` |

新版采集采用实际槽位语义，历史记录更新及导入保留槽号。未标注此版本的旧采集保留原有编号行为，避免根据单份新版分析重解释历史数据。已标注此版本、且完整原始请求能够覆盖所有已存密钥的压缩编号历史，在读取时重新提取槽位并纠正旧的 `uit` 误报。缺少原始请求的独立 JSON 文件无法可靠推回原槽位，需要重新采集。

## 验证范围

回归用例位于 `internal/engine/player_261056_test.go` 和 `frontend/tests/player-261056.test.ts`，覆盖校验值、舍入边界、固定槽与偏移槽、AES 模式及填充、独立请求参数、槽号存档和恢复，以及错误响应。四种模式使用合成 MP4 加密后运行完整引擎，逐字节比较解密文件，并通过媒体解码校验。旧版黄金样本及音频修复测试继续保留。

原分析文档明确说明尚未使用真实 `.sz` 样本确认新版本的完整会话、packet 与 sample 的对应关系，以及 `pwd_Audio` 的 PCM 变换。合成样本验证不能替代这些确认。现有音频修复流程继续运行，但不能据此保证还原所有新版 PCM 变换；本次未新增 PDF 解密功能。

本次 `npm run check` 已通过绑定生成、全套 Go 测试、354 项前端测试、生产构建、结构检查和仓库检查。真实播放器会话下的系统授权、证书信任及 TUN 抓包仍需实机验证，不能用本地 HTTPS 集成测试代替。

## 播放编排适配

播放编排原来独立校验版本，仅允许 `26.06.54`，因此已完成解密适配的 `26.10.56` 仍会显示「当前 SzPlayer 版本尚未适配」。状态检查和操作入口现统一使用 `internal/playerautomation/profiles.go` 中的版本配置，同时保留旧版支持。未知版本继续拒绝执行编排操作，状态文案显示实际检测到的版本。

使用 AppKit 加载本机 `PlayerControlBar.nib` 后，确认进度条、时间标签和音量滑块的对外标识仍分别为 `_NS:26`、`_NS:8`、`_NS:68`。nib 的 `NSOidsValues` 并非这些对外标识，不能直接据此更换标识。进度读取和完成判定继续使用原有数据契约。

新版 `-[PlayerControlBar viewDidLoad]`（arm64 地址 `0x1000e5a2c`）创建宽 300 点、居中的工具栏，单元格尺寸为 18 × 18 点，水平间距为 24 点；第一个单元格对应播放或暂停。旧版的固定位置不能直接用于新版。新版点击位置改为进度条中心向左 141 点、向下 23.5 点，仍优先执行 AXPress。新版完成观察器（`0x1000e6bf8`）保留写入进度 100 和完整时长标签的行为。

`BINGGAN_TEST_INSTALLED_SZPLAYER=1 go test ./internal/playerautomation -count=1 -v` 覆盖本机版本识别及 nib 实际加载，校验上述标识和版本配置计算出的按钮位置。原生控件测试覆盖两个版本的点击位置、AXPress 优先和结果不确定时停止重试。此次实机仅确认到登录页，尚未验证登录后的真实课程播放、暂停、倍速及自动切课。

## 连续课程的 Surge 转发检查

实机会话曾在第一节正常完成并保存后，于第二节启动采集时暂停。连续启停测试复现了 `surge-cli --raw rule match` 偶发返回退出码 1，同一查询在 200 毫秒后恢复成功；旧实现将单次查询失败直接返回给分流助手，助手随即退出。

`commandRunner` 现对已知的只读查询最多尝试 3 次，间隔 200 毫秒，所有尝试共用原有 4 秒时限，并支持取消。配置重载、规则增删和配置校验保持单次调用。最终失败日志记录固定的命令名称、退出码和尝试次数，不输出命令参数或原始诊断内容。

`internal/surge/command_runner_test.go` 覆盖短暂失败恢复、永久失败上限、取消操作及敏感信息保护；回归测试已在未修复代码的隔离副本上确认失败。`BINGGAN_SURGE_INTEGRATION=1 go test ./internal/surge -run 'TestNativeSurge(RepeatedCaptureSessions|RoutesOnlyShenzaoAndRestores)' -count=1 -v` 已通过真实 Surge 的 12 次连续启停及本地转发验证，并检查原配置逐字节恢复。这些检查验证课间转发重建，不替代完整课程队列的播放验证。

### 队列期间保持分流连接

播放编排现通过 `CaptureService.RoutingSession` 的原生通道持有整个执行队列的分流连接。第一节启动提取时建立转发；课间保存、清空接收缓冲和下一节启动只切换记录接收，不再撤销规则、重写配置或重复重载 Surge。每节课仍有独立的采集编号和保存记录。

主动暂停时，执行上下文仍在，分流连接继续保留，接收开关关闭。队列完成、主动结束或执行上下文因错误结束时释放连接；页面关闭或重载也会取消原生通道，由后端停止接收并恢复分流。释放过程完成后，任务才返回；恢复失败会记录错误并阻止不确定状态下的自动重连。

连接标识只保存在当前执行上下文中。队列的接收开关和缓冲清空操作必须携带匹配标识，避免手动采集或过期回调改动队列数据。没有队列连接时，手动采集保持原有启停流程。

`monitor_routing_test.go` 覆盖课间保留、页面丢失、手动采集隔离和恢复失败；前端两课测试确认只创建一个原生连接、保存两条独立记录，并已在优化前的隔离副本上确认失败。真实 Surge 的三课验证确认分流只建立一次、恢复一次，课间配置内容保持不变，最终原配置逐字节恢复。完整检查通过全部 Go 测试和 360 项前端测试。
